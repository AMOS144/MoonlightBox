# 前后端链路审查修复

## 本次范围

修复链路审查中确认的问题，不调整概率策略，不引入功能开关，不修改已有聊天或人物资料。

## 后端

- `branch_writer_busy` / `branch_busy` 归类为可恢复的运行时冲突。仍由 Job 的统一恢复策略处理退避和终态，不另加整任务重试循环。
- 计划的连续覆盖、15 分钟网格及引用要求集中为纯参数校验。普通日程和生活事件的提交工具先回传可修复错误；事务提交仍保留最新状态、来源归属和版本冲突保护。
- 生活任务的提交工具绑定当前分支的来源校验能力，错误引用不再等到 Executor 才被拒绝。分支身份由后端绑定，不要求模型填写。
- 新增 Runtime 任务保存 `project_id`。项目任务列表和流程状态共用归属条件，兼容历史上仅含 `branch_id` 的任务；已有显式项目归属的任务不跨项目回退匹配。
- 补齐生活事件嵌套 Schema 的字段说明，不给概率种子增加剧情、情绪或影响预算。
- 全量回归额外发现旧 V2/V3 分析入口把“取消中仍可续租”误解为“继续执行”。现在显式检查 `running` 状态，取消请求会中断分析；Worker 在处理退出后确认取消终态。

## 前端

- 聊天待发送消息按项目和分支隔离，并保存到当前标签页的 sessionStorage。刷新后未确认的发送显示为可重试，不自动重复提交。
- 失败重试沿用原 `client_message_id`，依赖后端幂等接收；失败内容保留，不覆盖用户正在写的新草稿。
- POST 成功但历史查询尚未确认时保留消息，直到 GET 返回对应记录再清理待发送副本。
- 切换分支重置页面局部状态；迟到的请求回执只更新原分支缓存。
- 输入法组合期间的 Enter 不提交。聊天记录请求失败提供明确提示和重试入口。
- HTTP 成功状态下的非法 JSON 明确返回 `invalid_response`，不再伪装成成功结果。

## 回归方式

- 新增后端回归覆盖 Planner 锁冲突恢复、任务项目归属、生活提交参数错误及修正后的接受回执。
- 新增前端回归覆盖发送失败重试、保留新草稿、输入法 Enter、跨分支迟到回执和刷新后恢复。
- Schema 清单测试检查嵌套字段说明。
- 旧事件分析兼容测试显式创建历史任务，不再假设普通导入仍自动启动已退役的事件评分流程；取消测试按取消请求、Worker 确认两个阶段断言。
- 重命名重复的时间检索测试模块，使后端测试可以统一收集运行。

自动测试使用临时数据库和模拟模型请求；不冒充真实供应商、真实图谱或实际聊天验收。
