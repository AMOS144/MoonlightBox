# 节点选择调查 Agent 实现说明

## 本次实现范围

对应 `specs/2026-09-14-node-selection-investigation-agent-design.md`。实现节点调查、增量候选、询问与恢复、原文定位、边界预览和用户确认。不自动创建历史分支，不编译历史节点人物画像，不修改 LightRAG 图谱。

旧 EventNode 数据和既有分支保留。新 `/projects/:projectId/events` 与 `/nodes` 均进入节点调查；旧页面放在 `/events/legacy`。画像发布后的下游入口已改为新 Agent；未配置图谱的导入不再自动回退旧事件评分器。

## 后端组织

`backend/moonlightbox/node_investigation/`：

- `prompts/investigator.md`：独立行为 Prompt，指导顺序调查、跨页追踪、间接理解和中性提问，不内嵌工具 Schema。
- `schemas.py`：模型工具参数、用户操作参数；模型不填写 Job、图版本、审批 hash 或候选修订号。
- `tools.py`：7 个调查工具；普通 RAG 使用现有 LightRAG 的 `naive` 向量检索，关系调查使用 `mix`。两者都将 Bundle/chunk 还原为原始 Message ID，不把 Bundle 映射行 ID 当消息 ID。
- `agent.py`：第 8 个工具 `submit_investigation_turn` 注册为唯一完成协议。使用现有 AgentLoopController 的 LangGraph、bind_tools、检查点、输入刷新、容量管理和 Phoenix。
- `store.py`：工作台业务状态、原始记录版本、候选修订、用户输入和边界审批的短事务。
- `jobs.py`：后台任务接线；提问正常完成 Job，保存 `waiting_for_user`，不占 Worker 等用户。
- `router.py`：用户启动、补充、回答、暂停、恢复、指定范围、浏览原文、预览和批准。
- `models.py`：只新增 `node_investigations` 一个业务表；不新增 AgentRun/Step/ToolInvocation 调用账本。

任务类型为 `node_investigation_turn`，由 `background` / `all` Worker 执行。认知模型与请求重试策略使用现有配置；没有新增云端客户端循环。

## 恢复与并发边界

1. 每份冻结材料只创建一个调查工作台，数据库唯一约束处理重复启动。Job 与排队状态在同一事务保存。
2. 同一调查只排一个活跃回合。用户在运行期间补充信息时只落输入，下一次模型调用前补入已有上下文，不取消当前模型请求。
3. `read_next_messages` 必须传已有游标。工具已保存进度、检查点尚未保存就重启时，重放相同游标仍得到原页，不跳过正文。
4. 模型保存草稿前若有未读用户补充，返回可修复工具错误；先理解用户纠正，再继续写。候选没有内容变化时不递增版本。
5. 模型提交时刚到的新输入交给下一回合，不撤销本轮、不丢输入。
6. 失败重试保留相同 Job/turn 和 Controller 检查点。累计预算及恢复次数沿用统一 Controller 规则；不会后台无限创建新 Job 绕过额度。
7. 显式暂停通过取消信号退出。同步数据库操作只能在边界取消；页面会显示“正在停止”，不宣称尚在执行的操作已经停止。

新增任务的策略声明集中在 `agent_runtime/policy.py`：单次墙钟 1800 秒、模型步数保险丝 256、工具调用保险丝 256；不是要求跑满的轮数。共享 Controller 处理临时故障、重复循环、上下文容量和恢复预算。数据库工具边界超时 30 秒，检索工具请求预算 300 秒；不能强制杀死任意同步 Python 操作。

## 材料、范围和确认

冻结消息清单按时间和源消息顺序稳定排列，指纹覆盖消息与参与者信息。顺序阅读区间、搜索结果、用户主动跳过区间分开保存。用户可以限定日期范围，覆盖率只统计范围内真实读取的条目，不拿游标位置冒充全量覆盖。

图谱未完成时原文仍可调查，但工具明确报检索不可用，不能转成“没有经历”。恢复时允许绑定后来完成且导入集合匹配的索引；已经绑定的图版本不跟着“最新版本”静默切换。

经历时间保留可解释范围，分支边界另行确定：

- 消息边界保存 `message_ref + before/after`，后端解析时区、包含条数、最后包含及第一条排除消息。相同秒的两条消息不会被混在一起。
- 空档边界不由模型补精确时间，用户须输入带时区的确切时刻。
- 预览绑定候选版本、冻结材料版本和 hash；批准时在事务中重新验证版本及原始材料。
- 确认结果保留批准时间和是否继续调查；默认停止。已批准候选不能被 Agent 静默改写。

## 前端工作台

`frontend/src/features/nodes/NodeInvestigationPage.tsx`：左侧候选逐张出现，中间显示经历理解、疑点、相关原文和起点预览，右侧显示简短工作进展及问答。

采用版本化快照轮询，不重建整页：卡片使用稳定 ID，旧版本响应不覆盖新版本，新增候选不抢选择或重置滚动。当前选择、输入草稿、圈选原文和请求幂等键保存在 sessionStorage。回答、不确定、跳过、纠正前提均绑定问题；刷新只是读快照，不自动启动新任务。

工作台可独立翻阅原文并圈选消息，请 Agent 调查附近经历；用户翻阅不计入 Agent 已读进度。公开进展最多保留最近 150 条简短业务活动，完整模型和工具调用仍以 Phoenix 为准，不展示隐藏思维链。

确认只交付节点选择结果。页面明确提示历史背景编译尚属下一阶段，不提供虚假的“历史分支已准备好”聊天链接。

## 验证与启用

离线测试覆盖：真实 Controller/Worker 的询问—恢复、工具错误回传、运行中新输入、失败检查点恢复、候选幂等、同秒边界、空档精确时间、材料变更拒绝、RAG 消息引用还原、作用域隔离、指定范围及跳过、重放同页、用户纠正保护。前端测试覆盖增量更新不重置选择/滚动/草稿，以及问题绑定和刷新不重复启动。

已执行前端生产构建、Ruff、数据库临时迁移测试，以及画像发布接入新调查 Job 的回归测试。这里验证的是协议与交互，不以模拟模型测试宣称真实调查质量已经验收。

本次没有改体验库、没有重启现有服务、没有发起真实云端调查。启用时，在现有环境确认数据库备份和正在运行任务后，应用 `0060_node_investigations` 迁移并重启本地 API / background Worker；前端进入 `/projects/<projectId>/nodes`。不要另建 worktree 私有数据库，也不需要 Docker。
