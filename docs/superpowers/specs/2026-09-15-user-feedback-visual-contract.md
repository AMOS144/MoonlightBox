# 用户反馈的统一约定

适用于导入、人物审核、起点调查、分支准备、聊天、设置和保留的辅助页面。

## 视觉

所有提示使用主题中的 Alert 样式：深色中性表面、细边框、小字号；警告只以金色细边提示，错误用低饱和色细边。不能使用整块红色或橙色背景。危险操作按钮仍保留危险色，不把操作风险隐藏掉。

不影响继续操作的缺失媒体使用状态提示，不当作导入失败。表单问题放在对应操作附近；初次加载使用骨架，后台刷新失败不清空已有内容。重试按钮保持次级样式，不与页面主操作争抢。

## 文案

说明发生了什么、已知的影响及下一步。只有业务代码确认保留了进度时才能承诺“进度已保留”，不能对所有故障统一做此承诺。

例如：`missing_strong_media_reference: 16` 改为“16 条表情消息暂未找到对应文件，不影响导入聊天文字。可以检查导出目录是否包含表情文件。”

HTTP/网络异常经统一消息转换层处理；后端状态字段也需转换，不直接展示错误码、堆栈、内部路径。保留明确的中文业务校验提示，不能把所有问题都变成“出错了”。未知技术错误使用安全的用户提示，原错误仍留在响应诊断信息或后台 Trace。

开发诊断不删除，但只在明确的诊断区域呈现。普通任务提示不要求用户理解 Sidecar、Patch、Worker 或 Phoenix。页面级异常提供重新加载和返回项目列表，不显示 React Router 默认英文堆栈；重新加载不能清理上传预览和草稿。

## 维护入口

- `frontend/src/app/theme.ts`：提示框颜色、间距、字号。
- `components/feedback/messages.ts`：用户错误说明与媒体提示。
- `components/feedback/AsyncState.tsx`：读取失败及重试。
- `components/feedback/RouteErrorPage.tsx`：页面异常恢复。

新增页面使用这些入口，不另建一套红色横幅或直接把 `error_code` 放进主界面。
