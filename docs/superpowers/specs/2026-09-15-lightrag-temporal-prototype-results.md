# LightRAG 时间检索小型原型结果

日期：2026-09-15。范围：隔离合成数据实验，不是生产集成验收。

## 结论

18 项断言通过。验证了两个可实施的接入位置：NanoVectorDB 相似度排序前限定候选；LightRAG 实体/关系关联片段选择前限定 source_id。没有修改安装依赖、共享图谱、数据库或启动模型调用。

复现命令（runtime-prune 根目录）：

```sh
sidecars/lightrag_sidecar/.venv/bin/python scripts/probe_lightrag_temporal.py
```

脚本输出完整 JSON，包括案例、版本、源码 hash 和未覆盖范围；临时向量库只在临时目录中使用，不调用保存，不访问真实 workspace。

## 实际调用的代码

- 已安装 `lightrag-hku 1.5.6`、`nano-vectordb 0.0.4.3`。
- NanoVectorDB.query 的 filter_lambda，使用人工二维向量验证候选范围，不代表中文语义质量。
- LightRAG `_find_related_text_unit_from_entities` 和 `_find_related_text_unit_from_relations`，采用真实 WEIGHT 选择路径，数量限制为 1。
- 原型自有的请求局部来源过滤及 KV 视图。没有替换、修改上游函数，也没有对全局共享对象设置时间条件。

## 主要实验

| 场景 | 观察结果 |
| --- | --- |
| 未来片段相似度更高，全库 top-1 后过滤 | 早期结果为空，复现旧方案缺陷 |
| 在 Nano 排序前限制早期候选 | 返回 early，不受未来片段挤占 |
| 限定后段、空集合、交替范围 | 返回各自范围内结果；空集合提前安全返回 |
| 实体关联来源中未来片段排第一 | 原选择器返回 late，选择前限制来源后返回 early |
| 关系关联来源中未来片段排第一 | 同样可在选择前限定范围 |
| 同一 timestamp 的两条消息位于节点两侧 | 根据消息序号正确裁剪，不用时间戳猜包含关系 |
| 跨界 chunk、未知映射 | 不冒充纯前段向量；跨界只验证原文裁剪，未知排除 |
| 请求交错执行 | 各自的来源集合和 KV 视图隔离，不修改共享图来源 |

## 不能据此宣称完成的能力

1. 真实 chunk 与原始消息映射：实验手工提供准确映射，尚未评估存量资产回填覆盖率。
2. 全量实体/关系候选的前置过滤：实验从给定实体/关系出发，未解决较早的实体 top-k 本身被后期实体占满的问题。
3. VECTOR 关联选择、完整 aquery 混合检索和上下文组装：未覆盖，不能把局部选择通过当作全路径无越界。
4. 跨界片段重新 embedding 与排序：只验证裁剪和排除策略，未验证补算流程。
5. 时间缓存身份、取消、大规模性能：未覆盖。脚本毫秒级执行耗时不代表真实系统查询延迟。
6. 图谱历史描述还原：合并描述仍可能包含未来信息，原型不解决这一问题。

## 对原设计的修正

`2026-09-14-node-conditioned-person-world-compilation-design.md` 第 7 节的“全局 top-k 召回后过滤”不能作为主要时间检索实现，应改为上述前置候选范围约束。返回消息过滤保留为最后一道校验，不能承担找回早期材料的职责。

下一步建议先只读统计真实 chunk 映射覆盖率，再制作完整 sidecar 检索适配原型，覆盖向量、实体、关系及上下文组装。是否需要维护小型上游补丁，应在该完整原型验证后确定。当前不开放正式历史分支，也不重建昂贵图谱。
