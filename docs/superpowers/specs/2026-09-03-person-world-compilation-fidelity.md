# 人物世界编译失真控制设计

## 1. 问题定义

人物背景编译不是把检索到的句子改写成更短的句子，而是把聊天中的多种陈述整理成一个带对象、时间和语气的世界模型。

失真并不只表现为“把上课写成学生”或“把讨论实习写成实习律师”。同一种错误可能发生在所有栏目：

- 把谈论第三人的职业写成目标人物职业；
- 把行业规则写成个人经历；
- 把计划写成已经发生；
- 把一次性活动写成生活规律；
- 把用户的偏好写成目标人物偏好；
- 把朋友的地点写成目标人物居住地；
- 把玩笑、反问、转述或引用文字写成事实；
- 把过去阶段覆盖当前状态，或把当前状态错误延伸到全部历史；
- 把多个不同人物的关系、经历和称呼合并到同一节点；
- 把模型归纳结果伪装成原始对话事实。

因此，修正目标不是增加某几个关键词，而是让每一条编译结果都能回答：

```text
谁在说？
这句话描述谁/什么？
它属于事实、计划、规则、转述还是推测？
发生在什么时候？
原文证据在哪里？
是否与其他时间或来源冲突？
```

## 2. 编译数据的最小语义单元

当前 `SourcedStatement` 只有文本、来源状态和文档 ID，无法表达上述信息。第一版应扩展为：

```yaml
text: string
source_status: direct | summarized | inferred | superseded
assertion_kind: self_fact | other_person_fact | general_rule | plan | desire | report | joke | question | unknown
referent: target_person | user | third_person | organization | place | general_topic | unknown
temporal_status: current | past | planned | recurring | one_off | timeless | unknown
valid_from: datetime | null
valid_to: datetime | null
source_document_ids: [string]
source_message_ids: [string]
evidence_quotes: [string]
qualifiers: [string]
```

所有栏目（职业、学历、地点、关系、偏好、规律、生活阶段和事件）都使用同一套语义字段，不能只给“工作”栏目加时间字段。

## 3. 编译流水线

背景编译分为四个阶段，阶段之间使用结构化结果传递，不让最后一步直接从长文本自由总结。

### 3.1 证据检索

针对每个栏目检索 LightRAG，同时保留：

```text
query
retrieval mode
document_id
chunk/reference_id
chunk text
message_id 映射
```

检索结果只是候选证据，不是最终事实。不能因为某个节点被检索到就直接归因给目标人物。

### 3.2 陈述解析

模型先逐条解析候选证据，输出结构化陈述：

```json
{
  "speaker": "target_person",
  "referent": "unknown",
  "assertion_kind": "unknown",
  "temporal_status": "unknown",
  "claim": "……",
  "evidence_quote": "……",
  "source_message_ids": ["……"]
}
```

这里必须允许 `unknown`。解析阶段不能为了填满字段而猜测。

### 3.3 对象、时间和语气归因

随后再判断：

- 句子的主语和被描述对象；
- 是个人事实还是一般规则；
- 是当前、过去、计划、重复规律还是一次性事件；
- 是直接表达、转述、引用、玩笑还是模型推断。

发言者身份只表示“谁发送了消息”，不自动表示“消息描述的是谁”。

### 3.4 归并与冲突处理

只有完成对象和时间归因后，才把多条陈述合并到人物背景栏目。归并时保留每条原子证据，不把相互冲突的陈述强行平均成一句话。

## 4. 通用编译提示词要求

编译系统提示词应包含以下不可省略的规则：

```text
1. 发言者、陈述对象和被提及对象是三个不同概念，必须分别判断。
2. 没有明确自我指向时，不得把内容归因给目标人物。
3. 行业规则、他人经历、转述和引用不能写成目标人物事实。
4. 一次性活动不能自动写成长期规律或身份。
5. 计划、愿望、假设和玩笑不能写成已经发生的事实。
6. 过去状态不能覆盖当前状态；当前状态也不能回填历史阶段。
7. 只有原文明确支持的内容才能标记 direct；跨消息归纳标记 summarized；合理但不确定的推导标记 inferred。
8. 证据不足时输出 unknown 或不写入确定身份，不得用常识补全。
9. 每条输出必须带真实来源文档、消息 ID 和短证据摘录。
10. 不得为了填满栏目而生成内容；没有可靠证据就返回空数组。
```

## 5. 当前状态与历史状态的编译方式

不能用一个问题同时要求模型总结“现在和过去”。应分开检索和输出：

```text
问题 A：目标人物在最新有效时间点明确表达的工作、学习、居住和关系状态是什么？
问题 B：目标人物过去曾经经历过哪些工作、学习、居住和关系阶段？
问题 C：哪些内容只是计划、愿望或可能性？
问题 D：哪些内容属于行业规则、他人经历或无法确定对象的谈话？
```

最终档案也按这四类保存。若新证据没有明确时间，状态只能是 `unknown`，不能自动归入 current。

## 6. 冲突处理

冲突不是错误数据，应被显式保留并解释：

```yaml
claim_a: 在国企工作
claim_b: 计划去律所
relation: different_time_or_plan
resolution: 两条都保留，分别标记 current/past/planned
```

如果两条陈述时间相同但对象、来源或语气冲突：

1. 保留两条原子证据；
2. 输出 `conflict` 或 `unknown`；
3. 不自动选择模型认为“更像真的”那条；
4. 在前端显示冲突来源，必要时进入人工审核。

“后来的消息覆盖早期消息”只有在后文明确表示状态变化时才成立，不能仅凭消息日期自动覆盖。

## 7. 来源追踪必须可用

当前人物档案中出现 `source_document_ids: []`，说明 LightRAG 返回的 `file_path` 与 MoonlightBox 的 Bundle 文档名没有正确映射。需要：

1. 建图时保存 `document_id → bundle_id → message_ids` 映射；
2. 读取 LightRAG reference 时同时保存 `file_path`、`reference_id` 和 chunk 内容；
3. 对来源文件名做稳定规范化，不能只用字符串完全相等判断；
4. 编译输出中的每条陈述必须能回到至少一条真实消息；
5. 无法回溯来源的陈述不能标记为 `direct`，也不应进入确定身份。

## 8. 编译结果校验

模型返回后，程序执行通用校验：

- `referent` 必须是允许的枚举值；
- `temporal_status` 必须是允许的枚举值；
- `source_message_ids` 必须属于当前项目消息；
- `source_document_ids` 必须属于当前图版本 Bundle；
- `direct` 必须有直接证据摘录；
- `current` 不能只由计划、规则、愿望或单次活动支持；
- `self_fact` 不能只由第三人或一般规则支持；
- `unknown` 不得被下游自动升级为确定事实；
- 同一陈述的来源、时间和对象不能在持久化时丢失。

校验失败时保留原始模型输出和错误原因，但不把它写入确定的人物档案。

## 9. 前端展示原则

前端不再把所有陈述放在同一列表里。每条内容至少显示：

```text
对象：目标人物/用户/第三人/一般规则/未知
时间：当前/过去/计划/重复/一次性/未知
来源：原话/历史归纳/上下文推导/旧阶段
证据：可展开的原始消息
```

“当前身份”区域只显示 `referent=target_person` 且 `temporal_status=current` 的内容。历史、计划、行业规则和对象不明的内容分别展示，不能混入当前身份。

## 10. 验收标准

使用完整聊天数据验收时，不只测试某几个词，而要覆盖以下通用场景：

```text
目标人物自述当前事实
目标人物描述用户
目标人物描述第三人
行业/组织一般规则
过去经历
未来计划
一次性活动
重复生活规律
引用消息
玩笑、反问和转述
同一主题的时间变化
相互冲突的来源
```

每个场景都必须满足：对象不误归因、时间不混淆、语气不升级、来源可追溯。

## 11. 第一版实施顺序

1. 扩展 `SourcedStatement` 的对象、陈述类型、时间和消息来源字段；
2. 修复 LightRAG reference 到 Bundle/message 的来源映射；
3. 将背景编译拆成“证据解析 → 归因 → 归并”三步；
4. 更新通用系统提示词，允许 unknown 和空数组；
5. 增加程序校验，阻止无来源或对象不明的确定事实进入档案；
6. 更新前端，分开展示当前、历史、计划、规则和未知内容；
7. 在人工审核前不自动覆盖已有当前状态。

本设计不针对任何单个案例增加例外规则，而是统一约束所有人物背景陈述的对象、时间、语气、来源和冲突处理。
