# 月光宝盒：前端产品体验与视觉设计探讨

日期：2026-09-14  
状态：设计提案，待确认；本文不表示页面已实施。  
范围：页面组织、阅读与操作方式、视觉层级、文案、响应式布局。不是一次后端 Agent 重构。

## 1. 为什么还需要调整

前两轮调整解决了部分问题：统一组件库、删除失效样式、缩小字号、减少宣传性文案、提高首屏信息密度。但现在仍然偏向操作台。

原因不只是配色，而是界面持续在向用户展示系统的组织方式：项目、流程、资产、版本、任务、审核、分支。它们是必要的产品机制，却不应该在所有页面都占据主要注意力。

目前可见的几个问题：

- 概览用“分支列表＋资料统计＋六阶段状态”组织内容，更像项目管理页。
- 人物背景一直处于可选择、可修订的状态。即使只想阅读，也会反复遇到操作入口。
- 起点调查突出 Agent 调查过程，却没有充分突出用户真正要选择的时间和经历。
- 同一套标题、卡片、状态、按钮结构被用于几乎所有页面，缺少阅读、选择、聊天之间的差异。
- 从“大标题、大卡片、抒情介绍”直接收缩到“紧凑表格”，提升了密度，却没有回答产品应该给人什么感受。

本次应调整内容的优先顺序，而不是再次更换一套装饰风格。

## 2. 产品定位：关系与对话为主，系统能力为辅

用户的主要目的不是管理图谱和 Agent，而是：理解一个人，找到想进入的起点，然后继续对话。

界面应建立三个明确的体验重心：

1. **人物**：名字、头像、已经整理的人物背景，以及用户对这些理解的修正。
2. **经历**：有日期、有上下文的具体事件，以及用户补充的线下经历。
3. **对话**：分支中实际发生的交流，包含时间、文字和可用媒体。

任务、模型、索引、图版本、调用日志是支撑能力。在等待、审核、错误或主动查看详情时出现，不作为日常浏览的主体。

这里的“有生活感”来自真实资料，而不是界面替用户渲染感情。没有对话摘要时不编一句开场白，没有照片时不生成替代记忆，没有事件时不造一条动态填满页面。

数字人对话与导入的真人历史仍需可区分。不能通过视觉弱化来源，让生成内容看起来就是对方真实说过的话。

## 3. 设计方向与取舍

### 3.1 建议方向：克制的私人资料与对话产品

保留现在的小标题、可读正文和紧凑操作，但采用以下调整：

- 用真实头像、姓名、时间和对话内容提供辨识度。
- 降低边框、金色、状态徽章和大面积操作容器的存在感。
- 阅读区域像资料，时间区域像经历序列，聊天区域像对话；不是每页都套相同卡片。
- 让编辑和诊断成为明确进入的模式，而不是默认覆盖整个界面。
- 页面有稳定的重心，允许次要区域留白，不要求所有空白都放统计项。

### 3.2 不采用的方向

| 方向 | 不采用的原因 |
| --- | --- |
| 大图、大标题、情绪化文案的展示页 | 抢占内容空间，难以长期使用，也容易制造虚假的情感氛围 |
| 全面仪表盘化 | 系统状态代替人物和对话成为主角 |
| 所有内容都压成高密度表格 | 适合版本或任务比较，不适合连续阅读人物背景和聊天 |
| 用背景照片、头像或装饰填满空白 | 可能喧宾夺主；原始照片还可能与当前人物、时间不对应 |

本方案不是在“好看”和“实用”之间各取一半，而是让不同内容使用合适的表达形式。

## 4. 保留用户主线，但不把主线常驻成六步操作台

继续遵守现有流程：

导入记录 → 确认人物与资料 → 审阅人物背景 → 调查并选择起点 → 准备分支 → 开始聊天。

与已有[用户主线设计](2026-09-14-unified-user-journey-and-frontend-design.md)的关系：业务阶段、对象作用域、版本约束及批准要求不变；本文提议调整这些能力在页面中的视觉权重。获批前，不用本文覆盖已经运行的业务规则。

主线应在以下时机出现：

- 首次进入且尚未准备好：展示当前步骤和一个主要操作。
- 等待系统处理：说明正在准备什么、哪些操作仍然可用。
- 需要用户确认：展示对应对象与待处理事项。
- 已有可用聊天：让对话成为入口，准备流程退为可展开详情。

多个分支可以处于不同状态，不显示一个覆盖整个项目的总进度。已有可用分支不因新资料正在整理而失去聊天入口。

### 4.1 导航不再按后端模块扩张

继续沿用四个主区域，先不增加新的顶级页面：概览、人物资料、选择起点、我的分支。

- “概览”内容改为人物与最近对话，而不是六步状态表。
- “人物资料”内部保留参与者、背景和相关资料入口。
- “选择起点”承载时间与经历的浏览、调查、补充。
- “我的分支”承载已有对话入口和分支管理。
- 模型、回归评估、历史事件与日志继续放在高级区域。

是否将“我的分支”更名为“对话”，应在原型审查时确认。不能只改名称，却保留另一套页面文案和路由提示。

## 5. 逐页设计

### 5.1 项目列表：以对象辨识，不以状态辨识

每个入口保留项目名称、已确认的人物信息和更新时间。名称仍以用户设置为准，不自动重命名为关系名称。

已有头像时可作为小尺寸识别元素；没有时使用姓名首字，不生成装饰头像。项目创建状态只在确实影响操作时显示。

不重复展示“保存真实对话”等产品介绍。列表为空时，简短说明支持的导入格式，并提供“创建项目”。

### 5.2 项目概览：人物与最近对话入口

概览分为两种业务状态，而不是两套无关页面：

**准备中**：显示人物或项目名称、当前待办、准备状态。下方允许阅读已经可用的资料。主操作对应真实的下一步，不出现不可用的“继续聊天”。

**已有可用分支**：主要展示最近使用的对话及可用分支，其次提供人物背景与起点入口。

建议布局关系：

```text
人物头像  人物名称 / 项目名称                  人物背景

最近使用的对话
分支名称 · 分支虚拟日期
最近实际消息预览                              继续聊天

其他对话入口                         需要处理的事项（仅在存在时）
分支名称、起点、最后消息              具体对象与操作
```

这个布局只表达区域关系，不要求添加照片封面、欢迎标语或大尺寸人物卡。

关键规则：

- 预览只能取该分支真实保存的消息，不取模型尚未提交的输出。
- 虚拟时间与现实更新时间分别命名，不混成一个“最近时间”。
- 用户上次正在修订背景或回答调查问题时，保留“继续上次工作”；不能为了突出聊天而抹掉原有恢复位置。
- 数据统计和完整六阶段状态移入资料详情或准备详情，不再常驻首页。
- 没有预览数据时只显示名称、起点和状态，不伪造内容。

### 5.3 导入与参与者确认：短而明确的表单

此处不需要营造情感氛围。重点是文件选择、解析结果、人物绑定及异常处理。

- 删除文件选择前后的重复格式介绍。
- 解析后将记录范围、条数、双方信息集中在同一区域，减少上下寻找。
- 把头像、名称、角色放在同一行，主次由字号和位置区分，不靠多层卡片。
- 媒体缺失、身份冲突等影响结果的问题展开显示；技术报告折叠。
- 正式保存后显示简短结果与下一步操作，不继续占用一个大型成功区块。

前端不能把“文件已解析”显示为“导入已保存”，也不能为了简化流程而跳过参与者确认。

### 5.4 人物背景：阅读与修订分离

这是本方案最重要的交互调整。

**默认阅读状态**：

- 顶部显示人物名称、背景版本状态及“修改背景”。
- 正文按现有七个栏目组织，不新增另一套人物分类。
- 显示总体理解和栏目内容，不为每个字段反复显示“已生成”和选择按钮。
- 推断、用户纠正、未知、冲突仍可识别。来源与解释可展开，不删除其数据。
- 增加轻量栏目定位入口；阅读长文时可直接跳到生活情境、实践规律等位置。

**用户选择“修改背景”之后**：

- 显示可选字段和选中状态，打开与当前修订对象绑定的右侧面板。
- 右侧承接补充说明、澄清、理解确认、修改预览和批准。
- 用现有字段 ID、选择对象和修订会话，不创建一套平行的编辑状态机。
- 已锁定范围保持锁定；前端不能通过退出模式解除后端锁定。
- “收起面板”“退出选择”和“取消修订”是不同操作。隐藏面板不取消任务，不丢弃待提交输入。

页面组织建议：

```text
人物名称    已发布 / 草稿                       修改背景
栏目定位：概况  身份  生活  关系  ……

默认：可读的背景正文

修订时：可选背景正文                修订对话与确认
```

不为了增加屏效而同时铺开全部心理模型维度和全部证据。栏目正文优先阅读，细分模型和来源使用展开层次。展示层不能擅自重写、压缩或丢弃已经发布的人物结论。

### 5.5 起点选择：时间与经历是主体

建议默认呈现“候选序列＋当前节点详情”，而不是始终铺开“候选、详情、执行日志”三个等权重栏目。

候选入口包含日期、具体事件标题、必要的来源状态。选中后，详情呈现相关对话、用户补充及起点边界。

- Agent 正在调查时，只显示简短进展；执行细节默认折叠。
- 有问题时，候选附近显示“待补充”，用户打开调查侧栏回答。
- 如果问题属于全局调查而非某个节点，放在调查入口，不错误地附到任意节点。
- 长时间没有聊天只是线索，不能直接渲染为“分手”“旅行”等已确认事件。
- 日期未知或仅有区间时如实显示，不为时间线整齐而补造精确日期。
- 候选更新后保留用户当前阅读位置；需要重新确认边界时明确提示。
- 确认按钮说明实际后果：当前只确认起点时，就不能写成“立即开始聊天”。

节点可以逐步出现，但不使用抢焦点、自动滚回顶部或持续重排制造“实时感”。

### 5.6 分支准备：具体状态，不是技术流水线

准备页需要说明准备对象、所选起点、当前阶段，以及是否需要用户介入。

主区域只展示当前实际任务，例如“正在整理该起点的人物背景”。详细任务、耗时和错误诊断可展开，不把全部内部节点画成常驻流水线。

- 失败时保留已完成工作，显示失败环节和有效重试操作。
- 没有真实进度数据就不显示百分比。
- 准备完成后保留稳定入口，由用户进入聊天，不突然跳页。
- 当前体验使用最新背景时必须标注，不声称历史隔离已完成。

### 5.7 分支列表与聊天：以交流内容提供辨识度

分支列表保持紧凑，但不只展示数据库式的名称与状态：后端有可靠消息预览后，增加一条实际最近消息，帮助用户识别对话。

状态正常时弱化徽章；准备中、失败或只读时明确显示。重命名等管理操作放在次级菜单，不和进入聊天同等突出。

聊天页面保留现有消息布局、媒体、时间分隔、虚拟时间和历史边界。下一轮不重新发明聊天界面。

- 顶部以头像、姓名和虚拟时间为主。
- 人物背景、起点和日程通过次级入口查看，不常驻占据消息区。
- 用户在阅读旧消息时，新消息提示不强行改变滚动位置。
- 调查和修订侧栏不把草稿、工具输出混入正式聊天。
- 技术故障与人物没有回复分别表达。未取得可信状态时，不编造“她正在忙”解释系统失败。
- 只有真实返回的状态才可显示为准备中或处理中；不使用虚假的输入动画维持气氛。

### 5.8 高级页面：允许保留工具型设计

模型、版本、评估和日志本来就是管理性任务，适合表格、筛选、状态和技术详情。它们不需要模仿聊天或人物档案。

统一的是字体、颜色、控件与错误处理，不是要求所有页面使用同一种信息结构。

## 6. 视觉语言如何落地

### 6.1 色彩与材质

- 沿用暖灰深色基础，不在本轮新增主题系统。
- 金色用于当前导航、主要操作和少量关键标记；不用于每个副标题、分隔线和卡片背景。
- 背景、阅读面和浮层控制在少数层级，不堆叠渐变、玻璃效果和多层阴影。
- 分隔优先使用间距或细线，只有真正独立的对象才使用有边框容器。
- 不给不同栏目各分配一种醒目的颜色，不让整页成为状态色集合。

### 6.2 排版与密度

现有 22px 页面标题、14px 正文可作为基础，聊天保留 15px。正文不是越小越专业；不继续全面缩字。

- 页面标题仅一层，不重复英文栏目名和中文大标题。
- 工具区紧凑，阅读区保留适合扫读的行距与段间距。
- 短数据适合行布局；长背景文字不为了填满宽屏而拉成一整行。
- 宽屏可使用辅助栏，但没有辅助内容时不预留永久空列。
- 不能把两张长度差异很大的阅读卡强行拉伸到相同高度。
- 衡量屏效要看可用信息和完成任务所需的滚动，不看屏幕填满比例。

#### 6.2.1 字体：先统一实际呈现，再讨论换字体

当前 `app/theme.ts` 使用 `-apple-system、BlinkMacSystemFont、Segoe UI、PingFang SC、Microsoft YaHei、sans-serif` 回退链。它没有指定一个需要下载的统一字体，也不能仅凭配置判断某台机器实际渲染了什么字体。字体存在性、中文覆盖与混排结果必须在浏览器中检查。

当前标题继承 Mantine 默认 700 字重，按钮常用 600，导航使用 500。虽然字号已经缩小，但粗标题、粗按钮、深色底和密集边框叠加，仍会显得生硬。问题不能仅归结为“字体不够好看”。

建议的字体方向是清晰、克制的中文无衬线，而不是艺术字、圆体或整页宋体：

- 中文正文、表单和导航使用同一中文 UI 字体策略；标题不另起一种字体。
- 第一版优先使用系统中文字体，不为品牌感立即下载大体积中文字体文件。
- 中文系统字体放在可控的回退链中，明确测试 Windows、macOS 与 Linux 的实际结果；不能只检查英文字体。
- 平台字体外观允许有合理差别，但必须维持字号、字重层级、行高和控件基线的一致性。
- 品牌字标如果需要另行设计，只影响“月光宝盒”标识，不扩散到标题、按钮或正文。
- 日志和标识符可使用等宽字体，普通日期、聊天和人物背景不使用等宽字体。

建议作为原型起点的字重与排版：

| 使用位置 | 字号 | 字重 | 说明 |
| --- | --- | --- | --- |
| 页面标题 | 22px | 600 | 不使用默认 700 作为所有标题的统一值 |
| 栏目标题 | 16–18px | 500–600 | 不与页面标题争夺注意力 |
| 人物背景正文 | 14px | 400 | 行高约 1.65，保留阅读节奏 |
| 聊天正文 | 15px | 400 | 延续既有聊天可读性，不跟随工具区继续缩小 |
| 导航、普通按钮 | 13–14px | 500 | 不把所有可点击文字都加粗 |
| 日期、来源等辅助信息 | 12px | 400 | 提高对比度，不用极淡颜色或进一步缩字 |

上述数值是设计提案，不是已经实施的字体配置。若目标字体没有中间字重，应先检查浏览器合成效果，不用大量任意字重“微调”掩盖字体本身的问题。

字体验收使用项目中的真实姓名、长段中文、引号、数字日期和中英文混排。需要检查实际渲染字体、100% 缩放下的可读性、系统缩放后的截断及控件对齐，不能仅根据截图中的边缘锐利程度下结论。

### 6.3 文案

| 场景 | 避免 | 建议 |
| --- | --- | --- |
| 首页 | 保存那些可以重新选择的时刻 | 不写欢迎标语，直接展示人物与对话 |
| 背景入口 | 一起理解她所处的世界 | 人物背景 |
| 调查标题 | 从头慢慢回看你们的经历 | 起点调查 |
| 修改操作 | 选择并对话修改 | 阅读态“修改背景”；编辑态“选择” |
| 不确定来源 | 反复说明 AI 如何猜测 | 简短“推断”标记，展开查看解释 |
| 技术失败 | 她暂时还没准备好 | 请求失败；保留输入并提供重试 |

简洁不能牺牲准确性。批准图谱、取消任务、采用新背景等有后果的操作仍需明确说明范围。

### 6.4 图标：语义先于装饰，形态与中文文字协调

当前不是引入了多个图标库，而是同一个 Tabler 图标库的使用方式没有收敛：

- `components/Icon.tsx` 固定 `stroke=1.8`，页面直接导入的图标多数沿用库默认 `strokeWidth=2`。
- 使用了 15、16、17、18、20、22、24 等不同尺寸，其中部分有实际用途，部分只是各页面自行选择。
- 有的图标单独使用，有的放在 28、38、44px 的彩色 `ThemeIcon` 背景中，产生不同的视觉重量。
- `timeline` 名称实际映射到电影图标，并用于“选择起点”；分支入口使用 Git 分支符号。实现概念被直接搬进了用户界面。

不建议先替换图标库。先从现有库中建立小范围、统一的语义选择，再和文字放在一起审查。如果同一组原型仍不协调，才评估替换整个家族，而不是逐页混搭。

#### 6.4.1 建议的语义

| 产品位置 | 建议表达 | 避免 |
| --- | --- | --- |
| 项目/人物入口 | 真实头像、姓名首字或人物轮廓 | 为每个人物显示数据库或文件盒 |
| 人物背景 | 人物或个人资料 | 柱状图暗示统计面板 |
| 起点选择 | 时间线或带时间含义的日历 | 电影胶片、播放按钮 |
| 已有对话入口 | 对话气泡，必要时配人物头像 | Git 分叉作为用户对话的主要标识 |
| 分支结构详情 | 分叉符号可以保留 | 将结构符号重复铺到所有聊天入口 |
| 继续/进入 | 右向箭头或右向小箭头 | 用斜向外链箭头表示普通站内跳转 |
| 高级设置 | 设置符号 | 在日常页面放置大量技术图标 |

图标不能单独承担不熟悉的业务含义。主要导航保留文字，不让用户先猜图标再理解操作。

#### 6.4.2 建议的形态与尺寸

- 使用同一家族的线性图标；不在普通导航中混合实心、轮廓、立体图标。
- 以 18px 导航图标、16px 行内操作图标为两档基础；空状态确有需要时使用 24px。
- 以统一的约 1.75 描边作为原型起点。原型验证后集中定值，不在页面中分别调粗细。
- 图标与旁边的中文 400/500 字重一起检查，不孤立评价线条是否“高级”。
- 默认继承文字颜色；选中时使用同一套强调色，不为每个功能配一种颜色。
- 普通导航和行内图标不加彩色底座、发光或阴影；需要点击的图标由按钮提供交互区域。
- 图标可见尺寸不等于点击区域。触屏仍需要足够的点击空间，不能为了紧凑把关闭按钮缩成难以点击的小点。
- 同类动作保持相同箭头、位置与间距；选中、悬停、禁用不能临时换成另一种图标风格。

没有帮助识别的图标可以删除。已写清楚“修改背景”的按钮，不必再加一个只起装饰作用的图标；人物入口优先使用头像，不再额外叠加人物轮廓。

#### 6.4.3 落地与检查

扩展现有 `Icon` 组件及其静态语义映射，集中维护尺寸和描边；普通产品页面逐步停止各自直接导入并配置相同语义的图标。组件库自身的下拉箭头、日期控件等内置图标不强行替换，避免制造另一套控件。

开发示例页增加一组“中文导航文字＋图标＋按钮”的对照，而不是只有单独图标墙。比较默认、选中、禁用与焦点状态，并在 Windows 实际浏览器中确认线条和文字重量。

验收时不能只看“所有图标都是 18px”；还要确认语义正确、形态统一、基线稳定，且图标没有比人物姓名和对话内容更抢眼。

## 7. 组件与代码组织

继续使用 Mantine、Tabler 和现有主题入口，不为了视觉调整引入第二套组件库。

建议职责划分：

- `app/theme.ts`：排版、色彩、间距和控件默认值。
- `components/Icon.tsx`：产品图标的语义映射与线条规范；不建立动态图标服务或另一套图标库。
- `ProjectLayout`：导航、页面容器、聊天专用布局、移动端外壳。
- `PageHeader`：标题与必要操作，不承载欢迎区和阶段介绍。
- 项目概览：根据已有资料和分支状态展示合适入口，不替后端推断业务完成。
- 人物背景阅读与选择：共享字段渲染和来源组件，仅交互模式不同，不复制两套 v3 展示逻辑。
- 起点候选列表与详情：保留同一调查对象和路由定位，侧栏只负责补充与过程展示。
- 分支入口：现有 `BranchCard` 可调整为对话行；确认差异确实无法复用前，不同时新增另一套相似组件。
- `AgentConversationPanel`：继续作为外壳，业务会话与批准规则留在各功能中。

不预先建立大量只包一层 UI 的抽象组件。先完成两个有真实复用需求的页面，再决定共享边界。

## 8. 状态、响应式与连续感

### 8.1 不因“美化”破坏已有工作

- 后台刷新保留已加载内容，不把整个页面替换成骨架。
- 切换阅读与编辑、收起侧栏、离开页面，不丢失用户输入或选中对象。
- 错误集中到受影响的区域；相同请求错误不在页头和正文重复占位。
- 主要入口保持稳定，后台完成不能自行改写用户选择的恢复位置。

### 8.2 窄屏

- 人物阅读单列，栏目导航仍能定位，不缩成难以点击的文字。
- 修订和调查侧栏使用抽屉或独立面板，关闭后返回原阅读位置。
- 确认操作不被虚拟键盘遮挡；键盘打开时仍可看清输入对象。
- 候选列表和节点详情可分步查看，不把三栏压成三个狭窄区块。
- 对话入口的预览可截断，完整内容在聊天中阅读；名称、状态和操作仍能辨认。

### 8.3 可访问性

以普通正文对比度至少 4.5:1 作为设计验收目标；选中、错误、推断不能仅靠颜色表达。图标按钮有可读名称，弹出面板后焦点可管理，关闭后焦点返回入口。触屏操作不能仅依赖悬停。

## 9. 数据依赖与实现边界

| 设计内容 | 当前可用基础 | 实现时需注意 |
| --- | --- | --- |
| 精简视觉和文案 | 现有组件、主题、页面 | 主要是前端调整 |
| 人物背景阅读/修订切换 | v3 字段、选择回执、修订会话 | 复用审批规则，不新增批准协议 |
| 起点候选突出、日志收起 | 已有候选、问题、调查活动 | 不能把全局问题错误关联到某个节点 |
| 首页实际对话预览 | 现有分支与消息读取能力 | 首页投影尚需核对/补齐预览字段，避免每个分支单独轮询消息 |
| 分支背景版本与准备状态 | 已有准备读取接口 | 不以 UI 推断版本可用或历史隔离 |
| 历史起点创建新分支 | 原主线文档列出的未完成后端链路 | 不属于本次美化能解决的能力 |

若要补首页聚合接口，先定义最近消息的角色、类型、时间含义、内容预览及失败回退；媒体用类型提示，不把资源 ID 当作消息内容。必要字段未接通时仍可展示现有分支入口，不阻塞页面。

## 10. 实施顺序与验收

### 第一阶段：审查三个核心页面原型

先使用现有真实资料做概览、人物背景阅读/修订、起点选择的原型。检查内容重心与交互，不先全面换色，也不先重写整个组件目录。

原型必须同时展示有数据、准备中、失败/待确认、窄屏状态，不能只展示最好看的一张静态图。

### 第二阶段：落实共享视觉与状态

收敛色彩、容器和排版；实现阅读/修订模式切换、侧栏恢复、顶部操作组织。保留现有用户主线和稳定 URL。

### 第三阶段：补对话型入口所需数据

接入可靠的最近对话预览，再把首页切换为人物与对话入口。无数据时使用明确回退，不伪造预览。随后统一项目列表、分支列表及次要页面。

### 第四阶段：删除被替换的展示路径

确认引用与路由后，删除旧概览统计展示、常驻流程表、重复阅读/编辑代码和失效样式。保留业务读取接口、历史资料兼容及诊断入口，除非有单独的退役决定。

### 验收问题

1. 已有分支的用户能否直接识别对方和上次对话，而不先阅读一张流程表？
2. 只阅读人物背景时，是否还被编辑按钮和诊断信息持续打断？
3. 想修改一个结论时，能否找到操作、看清选择对象并完成既有确认流程？
4. 起点页首先呈现的是经历与时间，还是工具调用和任务状态？
5. 错误、准备中、等待用户和人物暂未回复是否能够区分？
6. 返回页面、打开侧栏或后台刷新后，阅读位置与输入是否保留？
7. 首屏是否有主要内容和明确操作；留白是否来自真实内容少，而非重复包装？
8. 390px、768px、1440px 宽度下是否仍可阅读和操作，是否出现横向溢出？
9. 中文实际渲染字体与字重是否经过确认？标题、导航和按钮是否仍然过粗？
10. 起点、对话、人物等图标是否表达了用户概念，而不是后台实现？是否还混有多种描边和装饰底座？

验证采用少量交互测试与真实页面审查，不用大量快照测试代替设计判断。不以文件变少、卡片变多或页面填满作为设计完成标准。

## 11. 建议优先确认的设计决定

以下三点已获用户确认并进入实现：

1. 概览以人物和对话为主体，流程状态从日常首页退到准备/详情层。
2. 人物背景默认阅读，需要时进入修订模式。
3. 起点页面以时间与经历为主体，Agent 过程和询问按需展开。

这三点决定了产品会更像私人资料与交流空间，还是继续像后台操作台。配色、圆角与动效应服务于这些决定，而不是代替它们。

## 13. 按钮去重与项目入口复核

用户反馈卡片入口仍混乱后，项目列表调整为单列目录：项目名称为主标题，人物和资料更新时间为辅助，整行进入项目。概览去掉人物卡装饰背景与重复分支，聚焦当前对话；当前入口与恢复位置相同时，不再重复显示恢复按钮。统计仍折叠。

| 页面/区域 | 处理 |
| --- | --- |
| 所有项目、新建项目 | 创建入口仅在列表标题栏；空状态不重复创建。返回使用共享侧栏的“所有项目”，表单不重复增加返回按钮。 |
| 项目概览 | 去除泛化“打开下一步”，当前对话不重复列出；待办只去重按钮，不隐藏问题与失败说明。 |
| 全局阶段提示 | 移除与侧栏重复的“我的分支”；状态提示与重试保留。 |
| 导入、人物确认 | 解析成功后不再常驻扫描按钮；重选目录清空预览后恢复扫描。导入成功隐藏已完成提交按钮。别名批准/拒绝/暂缓为不同决定，保留。 |
| 背景阅读与草稿 | 重生成收进版本管理；侧栏已展开时隐藏打开按钮。已有分支时不重复展示整块起点交接。批准、取消、返回阅读保留各自含义。 |
| 起点调查 | 查看原文、预览边界、批准起点对应不同阶段，不能为了减按钮跳过确认；暂停和补充仍可独立使用。 |
| 分支列表、创建、准备、聊天 | 空列表不重复选择起点；创建页移除重复的分支列表快捷入口。准备重试、进入聊天、未读消息定位、发送等保留。 |
| 模型、评估、训练、地图、历史资料、高级设置 | 核对操作目的，保留选择答案、取消训练、地图筛选等独立操作；训练完成入口改为模型页，不再错误跳转旧时间轴。 |

范围是界面和导航收敛，不删除真实项目、模型、历史资料或测试聊天，不改变审批及 Agent 调度。

### 13.1 消除项目列表与项目内部的外壳切换

进一步反馈指出：左下角的返回箭头不符合“项目集合”的语义，打开列表后侧栏、品牌位置和内容对齐全部变化，造成明显割裂。修订为：

- “所有项目”移到品牌下方固定位置，图标采用同一 Tabler 体系的四格集合符号；不再放在侧栏底部伪装为返回。
- 列表、新建、项目内部路由共用一个持久的布局父节点，保持导航宽度、品牌、背景、手机抽屉和 main 容器；进入项目时仅增加项目专属导航项。
- 项目列表删除独立品牌与外层 main，列表和概览采用相同 1000px 内容宽度、相同上边距；创建资料流程的短表单采用下节统一的 760px 居中内容列。

### 13.2 创建与资料准备流程的布局收敛

创建项目、选择导出目录、解析预览、人物确认、后台整理共用 `SetupHeader` 和 `components/setup.css`，不再由各页独立决定表单宽度和操作区位置。

- 内容列最大 760px，在导航右侧主区域水平居中；标题、说明和字段左对齐，不把整个表单垂直居中，避免错误提示出现后上下跳动。
- 顶部四步位置提示只标记当前步骤，不伪造已完成状态，也不允许点击跳过确认；追加导入仍适用。
- 每步主要按钮位于内容末尾右侧；目录选择是可键盘操作的真实按钮，扫描成功后隐藏重复扫描入口，重选目录后恢复。
- 解析预览明确显示“已解析，尚未保存”；只有服务端确认成功后显示已保存。消息数量、日期、参与者为摘要，媒体细节折叠，失败原因仍可见。
- “我”和“目标人物”在宽屏并排、手机纵排，选择同一人时就地解释；创建、扫描和保存失败可重试，保留仍有效的输入。
- 手机外壳已有内边距，不再叠加外层限宽。修复了 768px 下创建页与导入页相差 8px 的问题。
- 背景准备延续相同列宽；正式人物背景阅读页保留宽阅读布局，不强行挤进短表单。

验证：构建、lint、14 个测试文件共 32 项测试通过。`scripts/frontend_setup_smoke.mjs` 用拦截 API 的模拟资料走完成功与失败重试，1440、768、390px 下共 30 个状态均无横向溢出，步骤之间列宽一致且居中。18 次写请求全部由模拟接口接收，真实写入为 0；没有创建真实项目、导入资料或启动 Agent。截图位于临时目录 `/tmp/moonlight-setup-mock-1J5Irn`。
