# 月光宝盒完整产品设计

## 1. 文档目的

本文定义“月光宝盒（Moonlight Box）”首个完整产品版本的范围、架构、数据模型、核心流程和验收标准。产品基于真实聊天记录复刻目标人物的表达风格，识别关系中的关键事件，并允许用户从历史节点创建新的分支对话。

本文是实施计划的上游规格。实施必须按里程碑推进，每个里程碑独立验收，不把所有功能一次性堆入单个版本。

## 2. 已确认的产品决策

- 运行形态：单用户本地 Web 应用。
- 硬件基线：Apple Silicon，最低 32GB 统一内存。
- 微调方式：必须支持本地 LoRA/QLoRA；使用 Apple 官方 `mlx-lm` 作为依赖，通过自有适配器接入，不 fork 完整训练项目。
- 数据导入：定义统一消息模型，首批支持 wxecho 导出的 CSV、JSON、TXT；不直接破解微信数据库。
- 时态人格：一个全局 LoRA 学习目标人物的表达风格，节点前的关系状态和记忆由时态检索提供。
- 节点质量：AI 自动发现候选节点，用户可以合并、删除、改标签并补充节点。
- 评测：保留真实回复作为盲测集；云端大模型评审功能默认开启，缺少提供商凭证时提示配置，用户可以主动关闭。
- 分支：允许从同一节点创建并保存多条独立分支，但不提供并排对比和自动差异分析。
- 隐私承诺：产品不作“所有数据绝不上传”的固定承诺；具体边界由本地功能和云端提供商配置共同决定。
- 安全边界：当前版本不强制显示“AI 模拟”标识，也不加入强制危机响应。该决策存在明确的误认和情感安全风险，见“已知风险”。

## 3. 范围

### 3.1 包含

1. 聊天记录导入、预览、角色映射、清洗和脱敏。
2. 对话事件分段、关键变化点检测、LLM 复核和用户审核。
3. 时序事件图谱，以及围绕该图谱的 GraphRAG 检索。
4. MLX-LM LoRA/QLoRA 数据集生成、训练、版本管理和评测。
5. 时间轴、节点证据查看和筛选。
6. 从历史节点开始的时态检索与分支对话。
7. 多条分支的独立保存、切换和回看。
8. 本地评测与可配置的云端大模型评测。
9. 后台任务进度、取消、失败恢复和日志摘要。
10. macOS 原生启动，以及不包含 MLX 训练进程的 Docker 辅助部署。

### 3.2 不包含

- 微信本地数据库破解或解密。
- 公网多租户账号体系。
- 多用户协作或权限系统。
- 移动端原生客户端。
- 分支并排对比和自动走向差异分析。
- 为每个节点单独训练一份 LoRA。
- 直接部署完整 Microsoft GraphRAG 索引流水线。

## 4. 总体架构

采用模块化单体：

- 前端：React + TypeScript。
- API：FastAPI。
- 业务持久化：SQLite。
- 向量索引：ChromaDB 本地持久化模式。
- 本地训练与推理：MLX-LM。
- 后台任务：独立 Python 工作进程，任务状态持久化到 SQLite，不引入 Redis。
- 云端评测：默认开启的提供商适配器；缺少凭证或提供商故障时不影响本地核心功能。

后端按业务边界拆分为导入、消息处理、事件分析、时序图谱、训练、推理、分支、评测和任务管理模块。模块通过显式服务接口通信，禁止前端或路由层直接操作模型文件和向量索引。

训练引擎通过 `TrainingEngine` 接口接入。首个实现为 MLX-LM，业务层只依赖训练配置、任务状态、适配器产物和评测结果，不依赖 MLX-LM 的内部文件结构。

MLX 依赖 macOS Metal，不能在普通 Linux Docker 容器中使用 Apple GPU。首版推荐使用 macOS 原生方式运行完整产品。Docker 仅用于前端、API 和非 MLX 任务的辅助部署，训练与本地模型推理必须由宿主机进程执行。

## 5. 核心数据流

### 5.1 导入和预处理

1. 适配器读取 CSV、JSON 或 TXT。
2. 将记录转换为统一消息模型。
3. 用户确认“我”和目标人物的身份映射。
4. 系统展示总量、时间范围、消息类型、无法解析行和示例预览。
5. 用户确认后写入原始事实层。
6. 清洗结果和脱敏结果另存，不修改原始消息。

清洗默认处理系统消息、重复消息、空内容和媒体占位符。单字回复不能一律删除：连续短回复可能共同构成目标人物的表达节奏，必须先按时间窗口合并，再由规则判断是否适合训练。

### 5.2 关键节点发现

不使用纯 GraphRAG 发现关键节点。节点发现采用四阶段混合方案：

1. **事件分段**：根据时间间隔、主题连续性和意图变化，把消息划分为连续对话片段。
2. **变化点候选**：综合回复间隔、主题嵌入距离、情绪变化、意图变化、冲突强度和关系状态变化生成候选边界。
3. **LLM 局部复核**：只读取候选边界前后的局部窗口，输出结构化判断。
4. **全局合并和排名**：合并重叠节点，并依据变化幅度、持续影响、冲突强度和因果中心性排序。

每个候选节点至少包含：

- 类型：争吵、冷战、升温、和解、疏远、分手或其他。
- 起止消息 ID。
- 节点前状态和节点后状态。
- 情绪标签、主题、冲突等级和重要度。
- 判断理由。
- 可追溯的原始消息证据。
- 模型版本、提示词版本和分析参数。

用户可以接受、删除、合并、拆分、改标签和补充节点。人工修订必须保留版本记录。

### 5.3 时序事件图谱与 GraphRAG

图谱围绕“事件”而不是传统知识图谱中的通用实体构建：

- 节点：对话事件、消息片段、人物状态。
- 边：时间先后、可能因果、同主题、状态延续、证据引用和分支起点。

GraphRAG 只用于节点生成后的关联、检索和解释，包括：

- 查找某个事件前的相关记忆。
- 解释争吵、冷战和和解之间的可能联系。
- 汇总关系主题和长期变化。
- 为分支对话提供有时间边界的上下文。

当前数据规模使用 SQLite 保存节点和边，不引入 Neo4j。图算法在应用层执行；向量检索通过 ChromaDB 完成。

### 5.4 人格微调

训练样本以目标人物的真实回复为输出，以此前有限窗口中的对方消息和必要上下文为输入。构建数据集时：

- 保留目标人物的句长、标点、口头禅、短回复组合和表情使用特征。
- 排除媒体占位符、系统消息、无法恢复语义的内容和高风险隐私字段。
- 按时间分割训练集、验证集和盲测集，避免相邻对话泄漏。
- 对每次数据集构建生成不可变版本和统计报告。

MLX-LM 使用量化基础模型时执行 QLoRA。训练配置、基础模型标识、数据集版本、随机种子、适配器和指标共同组成一个可复现的模型版本。

### 5.5 时态检索和分支对话

用户选择审核后的事件节点作为穿越起点。系统生成该时刻的状态快照，并强制执行：

`message.timestamp <= branch.origin_time`

该条件必须同时存在于业务查询和向量检索元数据过滤中。只在提示词中要求模型“忘记未来”不符合验收标准。

生成上下文包含：

1. 目标人物的全局表达风格和已选择的 LoRA。
2. 起点之前的相关事件和原始证据。
3. 起点时的人物情绪、关系状态和未解决主题。
4. 当前分支中新增的对话。

每条分支固定父分支、起点、数据集版本、模型版本、生成参数和状态快照。分支只追加新消息，不修改原始时间线。

## 6. 数据模型

### 6.1 原始事实层

- `Project`
- `ImportSource`
- `Participant`
- `Message`
- `AttachmentRef`

原始消息导入后不可由清洗和分析流程覆盖。

### 6.2 分析与模型层

- `Episode`
- `EventNode`
- `EventEdge`
- `EvidenceRef`
- `AnalysisRevision`
- `DatasetVersion`
- `ModelVersion`
- `Job`
- `EvaluationRun`

该层可以根据原始消息和版本化配置重新生成。

### 6.3 时间分支层

- `Timeline`
- `Branch`
- `BranchMessage`
- `StateSnapshot`

删除项目时必须清理数据库记录、向量集合、模型适配器、中间数据和缓存。

## 7. 产品界面

固定导航为：

`项目概览 → 数据 → 节点 → 模型 → 时间轴 → 分支 → 评测`

### 7.1 创建项目

- 上传 wxecho 文件。
- 映射聊天参与者。
- 预览格式和数据质量。
- 配置清洗、脱敏和媒体处理规则。

### 7.2 分析与训练

- 查看清洗统计和事件分段。
- 审核候选节点。
- 构建训练数据集。
- 选择基础模型和训练预设。
- 查看任务进度、日志摘要、取消、恢复和失败原因。

### 7.3 时间轴

- 按节点类型、主题、情绪和冲突等级筛选。
- 展开节点查看前后状态、判断理由和原始证据。
- 编辑节点或从节点创建分支。

### 7.4 分支对话

- 显示穿越起点和当时状态。
- 与数字人继续对话。
- 从同一节点另开分支。
- 通过列表切换和回看历史分支。
- 不提供并排分支对比或自动差异分析。

## 8. 后台任务和错误处理

任务状态包括等待、运行、成功、失败、取消和意外中断。任务进度和检查点持久化，应用重启后可以识别并恢复可恢复任务。

- 导入失败：报告具体文件、行号、字段和修复建议。
- 分析失败：保留已完成片段，仅重试失败片段。
- 训练前检查：Apple Silicon、统一内存、磁盘空间、模型兼容性和有效样本量。
- 训练中断：保留最近检查点和日志，不把不完整适配器登记为可用模型。
- 推理失败：区分模型未加载、内存不足、超时和上下文超限。
- 云端评测失败：提示密钥、限流、网络或提供商错误，不阻塞本地核心流程。

用户界面只展示安全、可操作的错误摘要；详细堆栈写入本地日志。

## 9. 评测与验收

### 9.1 人格复刻

- 留出真实回复，不参与训练。
- 对基础模型、仅检索版本和 LoRA 版本进行盲测。
- 人工从用词、句长、语气、标点、口头禅和上下文适配度评分。
- 可调用云端大模型进行同维度辅助评分。
- 训练版本必须优于基础模型，才标记为推荐版本。

### 9.2 节点发现

从现有样本中人工建立一小组黄金节点，记录节点范围、类型和证据。验收指标包括：

- 候选阶段召回率。
- 审核前节点准确率。
- 节点范围与人工标注的重合程度。
- 证据引用正确率。

指标阈值在实施计划的基线实验后确定，不能在没有基线数据时虚构数值。

### 9.3 时间分支

- 任意分支均无法检索起点之后的消息。
- 相同模型版本、状态快照和固定随机种子可以复现实验性输出。
- 分支消息不会修改原始消息或其他分支。

## 10. 测试策略

- 单元测试：格式适配、消息归一化、清洗、事件分段、变化点评分、节点合并、时间过滤和版本计算。
- 集成测试：导入到节点审核、数据集生成、训练任务登记、模型加载和分支创建。
- 黄金数据测试：节点发现和证据引用。
- MLX 冒烟测试：Apple Silicon 上使用小模型完成少量训练步和一次推理。
- 端到端测试：导入向导、节点编辑、任务恢复、时间轴筛选、分支创建和回看。
- 迁移测试：SQLite schema 升级后已有项目仍可读取。

耗时模型测试与普通测试分离，普通开发流程不自动下载大型模型。

## 11. 交付里程碑

1. **工程基础**：前后端骨架、SQLite 迁移、项目管理、后台任务框架。
2. **数据导入**：wxecho 三种格式、清洗、脱敏、预览和数据质量报告。
3. **时序事件图谱**：事件分段、变化点候选、LLM 复核、节点审核和图谱检索。
4. **人格微调**：数据集版本、MLX-LM 训练、模型版本、盲测和辅助评审。
5. **时间回溯**：时间轴、状态快照、时态检索、分支对话和分支回看。
6. **产品化**：云端评测适配器、错误恢复、完整测试、性能优化和部署文档。

每个里程碑必须在进入下一阶段前通过对应测试和可操作的演示流程。

## 12. 已知风险

1. **数据规模与质量**：当前样本约七千条消息，且时间跨度较短，可能不足以稳定复刻长期人格；产品必须区分表达风格复刻与真实人格推断。
2. **节点主观性**：关系转折点没有唯一真值，因此需要黄金样本、证据引用和人工审核。
3. **未来记忆泄漏**：普通向量检索容易返回起点后的高相似消息，必须实施双重时间过滤。
4. **Apple Silicon 资源限制**：32GB 设备应优先使用 7B/8B 量化模型；更大模型不能作为最低验收要求。
5. **云端数据边界**：云端评测可能发送真实或可重新识别的聊天片段；由于产品不作固定隐私承诺，界面和部署文档仍必须准确展示实际提供商和传输内容。
6. **模拟身份误认**：不强制显示 AI 标识会增加用户把生成内容视为真实人物意愿的风险。
7. **情感安全**：不配置危机响应意味着模型可能在高风险语境中继续角色扮演。

## 13. 原始数据与仓库安全

- `wxecho/`、原始聊天、脱敏中间文件、向量索引、模型权重、LoRA 适配器、密钥和 `.superpowers/` 不得提交到 Git。
- 仓库只保存格式无关的合成测试样本。
- 日志默认不记录完整聊天正文和云端密钥。
- 所有导出、删除和云端调用行为必须在界面中提供明确结果。
