# 前端结构与界面维护

## 开发与验证

```sh
npm run dev
npm run build
npm run lint
npm run test -- --run --maxWorkers=1
```

默认前端端口 5175，`/api` 代理到本地 8001。页面服务可用不等于 Agent 工作进程已经启动。

## 结构

- `app/`：应用提供者、路由、Mantine 主题与设计变量。业务页面按路由加载。
- `components/`：共享交互外壳。`PageHeader` 管页面标题，`feedback/` 管读取状态与阶段交接，`agent/` 管侧栏外壳。
- `features/`：按业务组织页面、类型、查询和样式，不按组件外观分类。
- `features/journey/`：消费后端流程状态，不在前端重新推断业务完成条件。
- `features/dev/`：仅开发环境开放的组件示例 `/dev/ui`。
- `index.css`：基础排版、项目导航、页面容器；不放聊天气泡或人物审核的专用规则。
- `features/branches/chat.css`、`features/world/world.css`、`features/spatial/spatial.css`、`features/nodes/nodes.css`：所属功能的专用布局。前三者在 `main.tsx` 加载，避免复用组件时漏掉样式；节点页样式随路由加载。

## 视觉约定

1. 保留暖金色深色主题。颜色、圆角、控件默认值在 `app/theme.ts` 维护；不要再建另一套全局调色板。
2. 普通页面使用项目统一容器和 `PageHeader`；标题 22px、正文 14px，页面顶部不堆叠栏目名、口号、副标题与已完成提示。聊天使用独立全高布局，正文保留 15px。
3. 每一区域一个主要操作。入口卡用 `interactive-card`；概览与列表复用 `BranchCard`，不重复维护状态映射。
4. 正常等待不是错误；错误使用可重试反馈。概览承担自己的读取错误，顶部不再重复相同红色提示。
5. 导航断点由 `ProjectLayout` 管理；不要重新加入旧版窄侧栏和底部导航覆盖规则。
6. 支持键盘焦点、窄屏折行和减少动态效果偏好。金色实心按钮采用自动文字对比度。

### 信息密度与文案修订

以人物、经历与对话为主体，不使用宣传式或拟人化引导。辅助说明只在解释操作、权限、风险或错误时出现。不得以缩短文案为由隐藏失败、推断来源或审批条件。

概览优先展示真实人物和已提交对话预览，资料统计与流程状态折叠；恢复上次调查/修订仍保留。人物背景默认阅读，修改时才显示字段选择；同一渲染器保留字段 ID、来源和锁定规则。起点页为候选与详情两区，补充和执行记录按需进入抽屉。聊天的资料抽屉只读分支绑定背景与日程。数据少的页面允许留白，不编造活动和统计填充空间。

图标统一从 `components/Icon.tsx` 使用，描边 1.75，导航 18px，行内操作 16px；不直接在业务页面导入 Tabler。中文优先系统字体栈，标题 600、按钮 500；不依赖网络字体。项目列表的头像与姓名由批量身份查询返回；首页和分支列表共用 journey 的最新已提交消息投影，不能用推理草稿做预览。

### 操作入口去重

同一页面、同一目的地、同一状态只保留一个主要入口。空状态用文字说明，不再复制标题栏按钮。概览当前对话不重复进入其他分支列表；恢复路径与当前入口相同时隐藏恢复按钮。待办仅去重操作，失败和审批说明仍显示。修订侧栏已经展开时不再出现“打开修订对话”；收起面板、返回阅读、取消修订语义不同，不能合并。成功后已完成的提交按钮移除，下一步入口保留。

所有项目采用单列目录，项目名优先、人物名辅助；同名不重复展示。目录及概览样式集中在 `features/projects/projects.css`，不继续扩大全局 CSS。

创建、导入、人物确认和背景准备复用 `components/SetupHeader.tsx` 与 `components/setup.css`：760px 水平居中内容列，字段左对齐，主要操作置于末尾右侧，手机自然折行。步骤提示只表示当前位置；解析与保存必须分开显示。后台准备沿用该布局，正式背景阅读保留宽布局。可用 `node scripts/frontend_setup_smoke.mjs 9224`（仓库根目录）通过独立浏览器调试端口走查模拟创建流程，所有 API 写请求由模拟接口拦截，不提交真实资料。

列表、新建与项目内路由统一挂在同一个 `ProjectLayout` 下，切换时不卸载外壳。“所有项目”是品牌下方固定的全局入口，使用 `projects` 四格图标，不再作为左下角返回箭头。项目内菜单仅在选定项目时出现；列表不重复渲染第二套品牌或外层 main，手机端也沿用同一导航抽屉。

## 本次整理边界（2026-09-14）

原全局 CSS 1,536 行，移除 176 个不再匹配页面的选择器分支，并把存活的业务规则按功能迁移。旧侧栏、旧事件时间线、旧原生表单与训练卡片样式不再保留。开发示例从 `journey` 移到 `dev`；项目数据类型从列表页面移到 `projects/types.ts`。

没有删除原始资料、数据库、媒体或历史聊天。业务模块引用检查没有发现完全孤立的 TypeScript 页面，不为凑删除数量而删除仍有路由或引用的文件。人物审核与纠正大组件尚可继续按职责拆分，本轮没有改变其审批状态机。

验收包括构建、静态检查、前端测试，以及独立浏览器的桌面/窄屏只读检查。没有发起真实聊天、训练、节点调查或画像重新生成；不宣称历史分支创建后端已完成。

本轮最终结果：构建与 lint 通过，12 个测试文件 / 24 个用例通过；1440px 与 390px 下共 20 项页面检查通过，无横向溢出或浏览器运行异常。截图：`/tmp/moonlight-journey-ui-wm4i3H`。入口 JS 从整理前约 735 kB 降至约 359 kB（未压缩，不含按需业务块及共享块）。全局 CSS 最终为 73 行，连同迁移的业务样式共 705 行。
